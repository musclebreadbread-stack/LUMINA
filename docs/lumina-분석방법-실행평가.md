# LUMINA 분석·평가 방법 직접 실행 평가

## 1. 감사 개요

- 대상: LUMINA 공개 서비스
- URL: https://lumina.jack.ai.kr/
- 실행일: 2026-09-04 (한국 표준시)
- 방식: 공개 운영 사이트를 Chrome에서 실제로 열고, 각 화면의 입력·선택·결과·공유 흐름을 직접 실행한 블랙박스 평가
- 범위: 홈에서 확인된 12개 방법과 방법론·참고문헌·개인정보·통합 리포트 보조 화면
- 목표: 각 방법의 실행 가능성, 결과 전달력, 근거·한계 고지, 장점과 개선점 확인

이 문서는 소스 코드 감사나 통계적 재검증 보고서가 아니다. 결과값의 산출이 사이트 화면에서 정상적으로 이어지는지, 사용자가 결과를 이해하고 안전하게 해석할 수 있는지를 중심으로 평가했다.

개인정보를 입력하지 않기 위해 모든 실행에는 합성 데이터를 사용했다.

인지능력의 표준화 파일럿은 “답변과 진행 상태를 익명 계정에 저장”하는 운영 저장 동의가 필수였다. 별도 사용자의 동의 없이 해당 저장에 동의할 수 없으므로 표준 파일럿은 시작하지 않았다. 대신 서버 저장 없이 브라우저에서 푸는 공개 연습 문항 5개를 실행했다.

## 4. 방법별 상세 평가

### 4.1 사주

실행 경로는 /saju였다. 1990-01-15 12:30, 서울, 성별 미지정, 양력·23시 경계 기본값으로 입력하고 사주 원국 보기를 눌렀다. 결과 경로는 압축된 /r/… 형태로 이동했지만 화면에는 “이 링크의 결과를 읽지 못했습니다.”가 표시되었다. 다시 입력하기 링크는 노출되었으나 유효한 사주 결과 블록은 생성되지 않았다.

장점:

- 양력·음력, 시각 모름, 시각 경계, 출생지, 성별을 입력할 수 있어 전통 계산에서 필요한 조건을 명시한다.
- 출생지 자동완성, 시간 모름 선택, 결과 공유 경로 등 실제 사용 흐름에 필요한 입력 구조가 있다.
- 사이트의 방법론 화면은 lunar-javascript와의 436개 케이스 비교 및 전수 대조 주장을 공개한다. 다만 이 감사는 그 주장을 재검증한 것이 아니다.

개선점:

- **최우선:** 생성한 결과 payload와 /r/… 디코더의 계약을 배포 스모크 테스트로 고정해야 한다. 날짜·시간·장소·성별·시각 경계 조합을 최소 3개 이상 넣고, 제출 후 사주 네 기둥이 실제로 보이는지 검사해야 한다.
- 오류 화면에 단순히 “읽지 못했습니다”만 표시하지 말고, 재시도·입력 재검증·오류 ID·지원 문의를 제공해야 한다.
- 제출 버튼과 결과 페이지의 상태를 구분해 “계산 중”, “결과 생성”, “결과 읽기 실패”를 사용자에게 명확히 알려야 한다.
- 공유 링크가 입력값을 압축해 담는 구조라면 링크가 민감한 출생 정보가 될 수 있다는 경고를 결과 생성 전후에 보여 줘야 한다.

평가: **P0 릴리스 차단 수준의 기능 장애.** 사주가 서비스의 대표 방법 중 하나인 만큼, 이 문제가 해결되기 전 전체 플랫폼을 정상 출시로 보기 어렵다.

### 4.2 점성술

실행 경로는 /astro였다. 저장된 합성 출생 정보를 사용해 새 출생 차트 계산을 실행했다. 초기 화면은 “새 출생 차트 계산”이라고 표시되었지만 버튼 명칭은 “사주 원국 보기”였다. 실행 후 /r/…/astro로 이동했으나 사주와 같은 “이 링크의 결과를 읽지 못했습니다.” 화면이 표시되었다.

장점:

- 출생 시각·장소가 천체 차트 계산에 영향을 준다는 전제를 입력 화면에서 설명한다.
- 사이트 방법론은 천문 계산 라이브러리와 비교 표본을 공개하고, 점성술 계산의 경험적 예측 검증 부재도 고지한다.
- 사주와 분리된 /astro 결과 경로를 갖추려 한 구조는 확장성 측면에서 적절하다.

개선점:

- **최우선:** 사주와 공유하는 결과 인코딩·디코딩 계층을 분리 검증하거나 공통 계약을 명시해야 한다. 현재는 점성술만의 결과를 평가할 수 없었다.
- “사주 원국 보기” 버튼은 “출생 차트 계산”으로 바꿔야 한다. 다른 방법의 버튼명이 남아 있으면 사용자가 잘못된 기능을 실행했다고 느낀다.
- 차트 결과가 오류일 때 천체표·하우스·행성 위치 등 최소 결과가 하나라도 표시되는지 테스트해야 한다.

평가: **P0 릴리스 차단 수준의 기능 장애.** 계산 엔진의 정확성보다 앞서 결과 전달 파이프라인을 복구해야 한다.

### 4.3 타로

경로는 /tarot였다. 78장, 정·역방향을 사용하는 화면에서 한 장·세 장·켈틱 크로스 세 스프레드를 모두 실행했다.

실행 결과:

- 한 장: 여사제 역방향
- 세 장: 과거 컵 여왕 정방향, 현재 바보 정방향, 미래 컵 열 역방향
- 켈틱 크로스: 10개 포지션 모두 카드·방향·키워드·성찰 질문·도상 설명 표시

장점:

- 스프레드 선택이 간단하고, 카드 수와 포지션 의미가 명확하다.
- 시드가 결과 URL에 포함되어 동일 링크에서 동일 카드를 재현할 수 있다.
- 카드별 키워드와 성찰 질문이 있어 예언보다 자기성찰에 초점을 맞춘다.
- 계산 방법과 시드가 결과 화면에 노출되어 재현성과 설명 가능성이 좋다.

개선점:

- 결과 화면에서 “카드 공개하기” 버튼이 이미 공개된 뒤에도 비활성 상태로 노출되어 상태 의미가 혼동된다. “공개 완료” 또는 “다시 뽑기”로 바꾸는 편이 낫다.
- 켈틱 크로스는 10장 설명이 한 번에 길게 이어진다. 먼저 핵심 요약을 보여 주고 포지션별 세부 내용을 접을 수 있게 해야 한다.
- 시드와 긴 URL을 그대로 공유할 때 브라우저 기록·스크린샷·메신저에 결과가 남을 수 있음을 안내해야 한다.
- 카드 공개 애니메이션을 제공한다면 reduced-motion 설정과 키보드 사용 시에도 같은 정보가 즉시 노출되어야 한다.

평가: **정상.** 계산·재현성·성찰형 콘텐츠는 강점이고, 결과 길이와 상태 명칭이 주요 개선점이다.

### 4.4 수비학

경로는 /numerology였다. 1990-01-15와 HONG GILDONG을 입력하고 숫자 보기를 실행했다.

실행 결과:

- 생명 경로수 8: 성취·실행력 중심 설명
- 이름/운명수 4: 체계·근면 중심 설명
- 연·월·일 합산과 로마자 문자값 합계 67 등 계산 trace가 표시됨
- 결과 URL에 year=1990&month=1&day=15&name=HONG+GILDONG이 노출됨

장점:

- 이름 입력이 선택 사항이고, 이름을 비워 두면 생명 경로수만 계산된다는 설명이 명확하다.
- 계산 과정을 직접 보여 줘 결과가 임의로 나온다는 인상을 줄인다.
- 역사적 참고문헌과 “미래 예측으로 과학적 검증을 받은 방법이 아니다”라는 한계 고지가 있다.

개선점:

- “운명수”라는 이름은 결정론적 의미를 강화할 수 있다. 사용자 화면에서는 “이름 숫자 요약”처럼 중립적 표현을 우선하고 전문 용어를 보조로 두는 것이 좋다.
- 로마자 이름을 요구하므로 한글 이름 사용자가 어떤 표기 규칙을 따라야 하는지, 대소문자·공백·하이픈을 어떻게 정규화하는지 설명해야 한다.
- 실제 이름을 입력하면 결과 URL query string에 이름이 보인다. 개인정보처리방침의 “이름 등 식별 정보는 링크에 담기지 않는다”는 설명과 실제 동작이 충돌하므로, 이름을 URL에서 제거하거나 정책과 구현을 일치시켜야 한다.
- 이름이 포함된 결과를 공유하기 전 “링크에 입력값이 포함될 수 있음” 확인 단계를 제공해야 한다.

평가: **정상이나 개인정보 안내 불일치가 있음.** 기능보다 URL·정책 계약을 먼저 정리해야 한다.

### 4.5 성향검사 Big Five / IPIP-50

경로는 /psychometrics였다. 50문항에 모두 3점 “보통이다”를 선택하고 결과 보기를 실행했다.

실행 결과:

- 결과 페이지: IPIP-50, 문항 50개
- 다섯 요인 모두 원점수 30/50, 평균 3.0
- 요인별 T 점수·백분위·참고 표본·신뢰도 α·SEM·95% 구간 제공
- 중립 응답 100%라는 해석 주의 문구와 역채점 문항 표시
- MBTI 유형 분석 링크, 통합 리포트, 공유·PDF·이미지 저장·재검사 제공

장점:

- 50문항 진행률과 응답 선택지가 명확하다.
- 원점수뿐 아니라 신뢰도·측정오차·참고 표본을 보여 줘 심리 측정 화면으로서 설명력이 높다.
- 영어권 공개 표본이며 한국 인구 규준이 아니라는 한계를 숨기지 않는다.
- 결과가 성격을 단정하지 않고 강점·주의점·성찰 질문으로 연결된다.

개선점:

- 50문항을 한 화면에 길게 배치하면 피로가 크다. 5~10문항 단위 페이지, 이전·다음, 임시 저장, 미응답 위치 복귀를 제공해야 한다.
- 모든 문항에 3점을 준 합성 실행에서 원점수는 모두 같지만 백분위는 요인별로 8~56백분위까지 크게 달랐다. 외국 참고 표본과 T 변환의 결과일 수 있으나, 사용자에게는 “중립인데 왜 낮은가”로 보인다. 원점수·참고 백분위·해석의 관계를 한 화면에서 더 크게 설명하고, 중립 응답이 과도하면 해석 보류 배지를 표시해야 한다.
- T 점수와 10~50 원점수의 차이를 초보 사용자도 이해할 수 있는 짧은 예시로 설명해야 한다.
- 결과가 매우 길다. 상단에는 5요인 요약과 가장 중요한 3개 관찰만 두고, 신뢰도·규준·역채점·문헌은 접을 수 있는 세부 섹션으로 구성하는 것이 좋다.

평가: **정상.** 현재 플랫폼에서 방법론 투명성이 가장 높은 흐름 중 하나지만, 해석 강도와 화면 길이 조정이 필요하다.

### 4.6 MBTI 유형 분석(비공식)

경로는 /psychometrics/types이며 별도 문항 검사가 아니라 Big Five 결과에서 파생되는 참고 해석이다. 50문항 응답 결과의 유형 링크를 확인하고 결과 페이지를 열었다.

실행 결과:

- 결과 코드: ?STP-?V
- 확실성: 0%

## 5. 방법론·정책 화면 확인

### 공개 검증 방법론

/methodology에서 다음과 같은 플랫폼 자체의 검증 주장을 확인했다.

- 사주: lunar-javascript 독립 오라클 대비 436개 케이스 네 기둥 100% 일치
- 점성술: 20개 차트와 2020~2030년 5일 간격 표본 등 8,030건 비교
- 일진: 1900~2100년 73,414일 대조
- Big Five: 품질 필터 후 공개 IPIP 자료 551,607행 집계
- 타로·수비학: 시드와 문자값 산술의 결정론적 재현성 테스트

같은 화면에서 점성술 표본이 전 시각을 보장하지 않고, Big Five가 영어권 공개 표본이며 한국 인구 규준이 아니라는 한계도 확인됐다. 검증 수치와 한계를 함께 공개하는 방향은 장점이지만, 이번 운영 실행에서 사주·점성술 결과 디코더가 실패했으므로 배포 후 통합 테스트가 단위·엔진 검증만큼 중요하다.

### 개인정보처리방침

/privacy는 회원가입·개인별 서버 저장이 없고, 출생 정보는 localStorage에 남으며, 공유 결과는 압축된 입력값을 링크에 담는 구조라고 설명한다. 그러나 실제 수비학 결과 URL에는 이름이 query string으로 표시됐다. 정책 문구와 실제 동작을 맞춰야 한다.

또한 개인정보처리방침과 이용약관 모두 “초안이며 게시 전 법률 검토가 필요”하다고 적혀 있다. 공개 서비스 운영 전에는 실제 처리 흐름·광고 파트너·접속 로그·공유 링크·인지능력 파일럿 저장을 포함해 법률 검토를 완료해야 한다.

## 6. 직접 실행에서 확인된 브라우저·UI 품질

- 결과 화면의 제목·랜드마크·폼 역할·버튼명·이미지 대체 텍스트가 대체로 제공되어 접근성 정보 구조는 좋은 편이었다.
- 결과 페이지에는 공유하기·링크 복사·PDF 저장·재검사 등 후속 행동이 공통적으로 제공됐다.
- 링크 복사 성공 시 버튼명이 “링크를 복사했습니다”로 바뀌어 즉각적인 피드백이 있었다.
- 배경음은 기본 꺼짐 상태였다.
- 여러 결과를 확인한 뒤 /integrated-report를 열었을 때 “완료 결과 0”과 “브라우저 저장소를 사용할 수 없어 현재 세션 메모리에만 보관” 안내가 표시되었다. 자동화 브라우저의 저장소 제한일 가능성도 있으므로 일반 사용자 브라우저에서 재현 여부를 확인해야 한다.
- 브라우저 콘솔에서 Three.js의 THREE.Clock deprecated 경고가 반복 관찰되었다. 즉시 기능 장애는 아니지만 라이브러리 교체 전에 정리할 기술 부채다.
- 이번 감사에서는 실제 소스 코드, 다중 브라우저, 실기기, 375px·768px·1440px 전체 뷰포트 조합, axe 자동 검사, reduced-motion을 독립적으로 검증하지 않았다. 시각·반응형·자동 접근성 결과는 **추가 검증 필요**로 남긴다.

## 7. 우선 개선 순서

1. 사주·점성술의 /r/ 결과 디코더와 배포 스모크 테스트 복구
2. 실제 URL의 입력값 노출과 개인정보처리방침의 이름 처리 문구 정합성 확보
3. 홈·상세·동의 화면의 인지 문항 수와 IQ 관련 명칭 통일
4. Big Five·다크 트라이어드·EQ에 중립 응답 품질 플래그와 참고 백분위 경고 추가
5. 27~50문항 검사에 페이지 나누기·복귀·중간 저장·응답 품질 안내 추가
6. MBTI 파생 결과의 진입 링크와 물음표 경계 표시 개선
7. 긴 결과 페이지의 요약 우선·세부 접기 구조와 모바일 표 최적화
8. 콘솔 deprecated 경고 제거 및 375px·768px·1440px·키보드·reduced-motion 자동 회귀 테스트 추가

## 8. 최종 판단

LUMINA는 계산 근거, 신뢰도, 번역·규준 한계를 화면에 직접 공개하려는 방향이 뚜렷하고, 타로·심리 평가·운세·궁합의 결과 경험도 상당 부분 완성되어 있다. 특히 애착·다크 트라이어드·EQ에서 자기진단과 미래 예측을 경계하는 문구는 강점이다.

다만 사주와 점성술의 핵심 결과가 운영 URL에서 읽히지 않는 문제는 단순 카피 개선이 아닌 서비스 기능 장애다. 개인정보 URL 정책 불일치, 인지능력의 IQ 표현·문항 수 불일치까지 함께 해결한 뒤 “전체 분석 방법이 정상 실행된다”고 판단하는 것이 안전하다.

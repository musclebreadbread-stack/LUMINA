# LUMINA 통합 자기초상 설계

> 작성일: 2026-08-29
> 상태: 대화형 설계 승인 완료, 서면 검토 대기
> 대상: LUMINA의 여러 분석 결과를 근거에 맞게 종합하는 로컬 우선 MVP
> 후속 분리: 제한형 AI 문장화, 계정 동기화와 Postgres RLS

## 1. 목적

LUMINA는 과학적 평가, 문화적 해석, 상황적 성찰, 관계 분석을 함께 제공한다. 현재 플랫폼은 사용자가 어떤 분석을 완료했는지는 알 수 있지만, 서로 다른 결과를 공통 형식으로 보관하고 근거 수준을 보존한 채 종합하는 계층은 없다.

이번 기능의 제품명은 **통합 자기초상(Integrated Self Portrait)**으로 한다. 사용자는 여러 결과에서 반복되는 주제, 상황에 따라 달라지는 모습, 근거가 부족한 가설, 직접 확인할 작은 행동 실험을 하나의 갱신 가능한 리포트에서 본다. 첫 화면은 결과를 기억하기 쉬운 레이어 조합형 캐릭터와 한 줄 자기초상으로 시작하고, 사용자가 원할 때 각 문장의 근거와 한계까지 내려갈 수 있어야 한다.

이 기능은 진단, 치료, 채용, 교육 배치, 보험, 법률 또는 미래 보장에 사용하지 않는다. 캐릭터는 결과를 요약하는 시각 표현이지 새로운 점수나 사람의 고정 유형이 아니다.

## 2. 현재 구조와 해결할 문제

현재 코드에는 다음 기반이 있다.

- `src/lib/analysisCatalog.ts`: 분석별 근거 수준, 목적, 버전, 한계를 관리한다.
- `src/lib/analysisGroups.ts`: 고정된 검사 개수 대신 카탈로그를 근거 수준과 목적에 따라 묶는다.
- `src/lib/explorationLog.ts`: 브라우저에서 분석 완료 여부와 시각만 기록하며 점수나 응답은 저장하지 않는다.
- `src/lib/assessmentRun.ts`: 일부 평가 실행의 버전 있는 파생 요약을 세션에 보관한다.
- `src/lib/shareCode.ts`: 과학 평가 6종의 원문 응답 없는 공유용 파생 요약을 제공한다.
- `src/components/home/SelfAtlas.tsx`와 `SelfAtlasGrid.tsx`: 완료한 분석을 자기 탐색 지도에 표시한다.
- `src/lib/nextLens.ts`와 `src/components/report/NextLensList.tsx`: 완료 이력을 바탕으로 다음 분석을 제안한다.

현재의 핵심 결손은 다음과 같다.

1. 완료 기록은 있지만 여러 결과를 비교할 공통 결과 계약이 없다.
2. 같은 주제를 재는 결과와 전혀 다른 의미의 결과를 구분하는 비교 가능성 규칙이 없다.
3. 과학적 결과와 문화적·상황적 해석을 한 화면에서 안전하게 분리하는 종합 모델이 없다.
4. 결과가 바뀌거나 도구 버전이 올라갔을 때 기존 종합 리포트를 재계산하는 정책이 없다.
5. 현재 시각 경험은 개별 분석 카드 중심이며, 여러 결과가 한 사람의 이야기로 연결되는 대표 화면이 없다.

## 3. 승인된 핵심 결정

1. 리포트는 **근거 분리형**으로 설계한다. 과학적 결과와 문화적 해석은 같은 화면에 있을 수 있지만 같은 점수나 확신도로 합치지 않는다.
2. 사용자는 서로 다른 개인 분석 3개를 완료하고 그중 현재 카탈로그에서 사용 가능 판정을 받은 서로 다른 과학적 평가가 2개 이상일 때 통합 자기초상을 연다.
3. 1차 저장은 **로컬 우선 + 선택 동기화**다. MVP에서는 파생 요약만 브라우저에 저장하고 원문 응답과 출생 정보는 저장하지 않는다.
4. 종합 엔진은 **검증형 하이브리드**다. 규칙과 근거 그래프가 주장을 확정하며, AI는 후속 단계에서 허용된 주장만 문장화한다.
5. 대표 이미지는 **레이어 조합형 캐릭터**다. 로컬 에셋을 결정론적으로 조합하며 민감 특성을 추론하지 않는다.
6. 첫 화면은 **살아 있는 자기 초상** 구조다. 캐릭터와 한 줄 통찰을 먼저 보여 주고, 근거·긴장·실천으로 점진적으로 깊어진다.

## 4. 범위

### 4.1 이번 MVP에 포함

- 과학 평가 6종의 공통 결과 스냅샷 어댑터
- 사주·점성·수비학 3종의 출생 정보 없는 파생 요약 어댑터와 별도 상징 렌즈
- 구성개념 레지스트리와 결과 간 비교 가능성 표
- 반복, 보완, 맥락적 긴장, 단일 출처 가설을 찾는 결정론적 근거 그래프
- 출처, 반대 신호, 한계, 행동 실험을 가진 종합 주장
- IndexedDB 기반 로컬 결과 보관함과 삭제·내보내기
- 통합 자기초상 라우트, 홈과 개별 결과 화면의 진입점
- 로컬 레이어 조합형 캐릭터와 정지·감소 모션 대체 표현
- 한국어 우선 카피, 접근성, 성능, 개인정보 검증

### 4.2 이번 MVP에서 제외

- 생성형 AI 호출과 외부 모델로의 데이터 전송
- 계정 생성, 서버 동기화, 데이터베이스 마이그레이션, RLS 정책 변경
- 관계 분석 결과를 개인의 고정 특성으로 합치는 기능
- 오늘의 운세나 타로를 안정적 성격 증거로 누적하는 기능
- 임상 진단, 치료 권고, 채용·교육·보험·법률 의사결정
- 서로 다른 척도의 원점수, 백분위 또는 범주를 하나의 총점으로 합산하는 기능
- 교정되지 않은 확률이나 `신뢰도 87%` 같은 정밀 수치

제외된 AI와 동기화는 각각 개인정보·운영비·보안 경계가 독립적이므로 별도 명세와 승인을 거친다.

## 5. 분석 결과의 네 층

### 5.1 과학적 자기평가

Big Five 계열, Jungian, Dark Triad, 애착, EQ, 인지평가가 해당한다. 종합 엔진은 각 도구가 실제로 측정하도록 설계된 구성개념과 현재 검증 상태만 사용한다. 서로 독립적인 결과가 같은 주제를 지지할 때 반복 신호로 표시할 수 있지만, 점수 척도가 다르면 수치 합산은 금지한다.

### 5.2 문화적 자기해석

사주, 점성, 수비학이 해당한다. 이 결과는 과학적 주장과 나란히 볼 수 있는 **상징적 렌즈**다. 과학적 근거 등급을 올리거나 낮추지 않으며, 은유와 성찰 질문으로만 연결한다. 두 층은 색뿐 아니라 아이콘과 텍스트 라벨로 함께 구분한다.

### 5.3 상황적 성찰

타로와 오늘의 운세가 해당한다. 타로는 질문 원문 없이 사용자가 저장을 선택한 성찰 태그만 상황 기록으로 남길 수 있다. 오늘의 운세는 날짜가 지나면 안정적 결과로 취급하지 않는다. 두 결과 모두 통합 자기초상의 잠금 해제 개수에 포함하지 않으며 과학적 반복 신호를 만들지 않는다.

### 5.4 관계 분석

궁합은 두 사람 사이의 상호작용을 설명하므로 개인 자기초상에 흡수하지 않는다. 향후 별도의 **관계 초상**이 생길 때만 양쪽 당사자의 명시적 범위 안에서 사용한다. 이번 MVP의 잠금 해제와 종합 계산에서 제외한다.

## 6. 공통 결과 계약

도메인 계층은 UI 문장이나 이미지 경로가 아니라 의미와 출처를 전달한다. 아래 형식은 구현 방향을 고정하는 설계 계약이며 실제 구현 시 기존 타입 이름과 충돌하지 않도록 조정할 수 있다.

```ts
type ResultLane = "scientific" | "cultural" | "situational" | "relational";

type SignalValue =
  | {
      readonly kind: "band";
      readonly band: "low" | "mid" | "high";
      readonly standardizedScore?: number;
      readonly normId?: string;
    }
  | {
      readonly kind: "category";
      readonly code: string;
    }
  | {
      readonly kind: "observation";
      readonly code: string;
    };

interface ConstructSignalV1 {
  readonly constructId: string;
  readonly value: SignalValue;
  readonly descriptorIds: readonly string[];
  readonly limitationIds: readonly string[];
}

interface ResultSnapshotV1 {
  readonly schemaVersion: 1;
  readonly id: string;
  readonly analysisKey: string;
  readonly lane: ResultLane;
  readonly instrumentVersion: string;
  readonly scoringModelVersion: string;
  readonly completedAt: string;
  readonly locale: "ko" | "en";
  readonly signals: readonly ConstructSignalV1[];
  readonly referenceIds: readonly string[];
}
```

스냅샷에는 이름, 이메일, 계정 ID, 원문 응답, 자유서술, 출생 날짜·시각·장소, 관계 상대의 식별 정보가 들어가지 않는다. 표준화 점수는 해당 도구와 모집단에 유효한 규준 ID가 있을 때만 선택적으로 보관한다. 규준이 없거나 검증 상태가 불충분하면 범주 또는 관찰 코드만 사용한다.

분석별 어댑터는 세 가지 책임만 가진다.

1. 기존 결과 모델을 `ResultSnapshotV1`으로 변환한다.
2. 허용되지 않은 필드가 유입되면 저장을 거부한다.
3. 도구·채점·스키마 버전을 명시한다.

어댑터는 종합 해석을 하지 않는다. 종합은 별도 엔진이 담당한다.

## 7. 구성개념 레지스트리와 비교 가능성

`ConstructRegistry`는 구성개념 ID, 설명, 허용 문장, 금지 문장, 근거 자료, 적용 가능한 분석, 최신 검토일을 관리한다. `ComparisonRegistry`는 두 신호의 관계를 다음 셋 중 하나로 명시한다.

- `comparable`: 같은 또는 충분히 가까운 구성개념을 독립적으로 측정해 반복 여부를 살필 수 있다.
- `complementary`: 같은 점수로 비교할 수 없지만 서로 다른 관점으로 한 맥락을 설명할 수 있다.
- `not-comparable`: 의미·측정 목적·근거 체계가 달라 교차 해석하지 않는다.

비교 관계는 코드 작성자의 직감으로 추가하지 않는다. 각 관계에는 근거 문헌, 검토자, 검토일, 허용되는 해석 범위가 필요하다. 예를 들어 Jungian 범주를 Big Five 점수로 직접 환산하는 규칙은 두 척도의 동일성을 입증하지 못하므로 등록하지 않는다.

## 8. 근거 그래프와 종합 주장

종합 과정은 다음 순수 단계로 분리한다.

```text
ResultSnapshotV1[]
  → 버전·유효성 검사
  → 분석 층 분리
  → 비교 가능성 판정
  → EvidenceGraph 생성
  → SynthesisClaim[] 도출
  → 결정론적 한국어 문장
  → CharacterRecipe 생성
```

`EvidenceGraph`는 결과, 구성개념 신호, 비교 관계를 노드와 간선으로 표현한다. `SynthesisClaim`은 최종 사용자에게 보일 수 있는 최소 주장 단위다.

```ts
type ClaimKind = "repetition" | "complement" | "tension" | "single-source";
type ClaimStatus = "supported" | "contextual" | "exploratory";

interface SynthesisClaimV1 {
  readonly claimId: string;
  readonly kind: ClaimKind;
  readonly status: ClaimStatus;
  readonly sourceSignalIds: readonly string[];
  readonly counterSignalIds: readonly string[];
  readonly interpretationKey: string;
  readonly limitationIds: readonly string[];
  readonly experimentKey?: string;
}
```

등급은 다음처럼 사용한다.

- **지지됨**: 서로 다른 과학 평가의 비교 가능한 신호가 같은 방향을 지지하고 강한 반대 신호가 없다.
- **맥락 의존**: 과학 평가가 다른 방향을 보이거나 상호 보완 관계여서 상황 설명이 필요하다.
- **탐색적**: 한 출처뿐이거나 문화적·상황적 렌즈에서만 나타난다.

상충하는 결과를 오류나 모순으로 단정하지 않는다. 측정 상황, 시간, 구성개념 차이를 먼저 표시하고 사용자가 실제 생활에서 확인할 질문을 제시한다. 같은 결과 집합은 입력 순서와 관계없이 같은 주장 집합을 만들어야 한다.

## 9. 제한형 AI의 후속 경계

MVP는 결정론적 문장 템플릿만으로 완결된다. 후속 AI 문장화가 승인되면 다음 경계를 지킨다.

- 서버에서만 호출하며 클라이언트에 모델 키를 노출하지 않는다.
- 원문 응답과 출생 정보를 보내지 않는다.
- 입력은 이미 확정된 claim ID, 허용 descriptor, 근거 등급, 금지어 목록으로 제한한다.
- 출력은 JSON 스키마로 검사하고 입력에 없는 주장, 진단어, 점수, 미래 보장을 포함하면 폐기한다.
- AI가 실패하거나 사용자가 끄면 같은 claim을 결정론적 템플릿으로 즉시 렌더링한다.
- 외부 전송 전 별도 동의를 받고 전송 항목과 보존 정책을 설명한다.

AI는 결과를 결정하지 않고 표현만 바꾼다.

## 10. 로컬 결과 보관함

MVP는 IndexedDB에 파생 스냅샷과 생성된 보고서 메타데이터만 저장한다. 기존 `explorationLog`는 완료 표시와 추천에 계속 사용하되 점수 저장 책임을 추가하지 않는다.

저장소는 다음 기능을 제공한다.

- 스냅샷 추가, 조회, 결과별 제외, 삭제
- 전체 결과 삭제
- 개인 확인용 JSON 내보내기
- 스키마·도구·규칙 버전 검사
- 새 규칙 버전이 생기면 기존 보고서를 덮어쓰지 않고 `재계산 필요` 표시
- 저장 실패, 용량 부족, 브라우저 차단 시 메모리 전용 모드와 복구 안내

잠금 해제는 **서로 다른 개인 분석 3개 + 현재 카탈로그에서 사용 가능 판정을 받은 서로 다른 과학 평가 2개 이상**이다. 과학 평가 2개와 안정적 문화 해석 1개 조합은 가능하다. 같은 분석의 재검사는 하나의 방법으로 세며 최신 결과를 기본 선택하고 과거 결과는 변화 보기에서만 사용한다. 상황적 성찰과 관계 분석은 잠금 해제 개수에 포함하지 않는다.

브라우저 로컬 저장은 기기 계정에 접근할 수 있는 사람으로부터 데이터를 보호하는 암호화 저장소가 아니다. UI에서 이 한계를 설명하고 공용 기기에서는 저장하지 않는 선택을 제공한다.

## 11. 통합 자기초상 정보구조

승인된 첫 화면의 순서는 다음과 같다.

1. **대표 캐릭터와 한 줄 자기초상**: 현재 결과를 기억하기 쉬운 언어로 요약한다.
2. **왜 이렇게 해석했나요?**: 사용된 분석, 근거 등급, 한계로 바로 이동한다.
3. **과학적 관찰 / 상징적 관점**: 두 층을 병렬로 보여 주되 라벨과 색, 아이콘으로 분리한다.
4. **반복해서 나타난 나**: 여러 독립 결과에서 함께 나타난 주제다.
5. **상황에 따라 달라지는 나**: 긴장을 상황 질문으로 풀어낸다.
6. **아직 탐색적인 가설**: 한 출처 또는 문화적 렌즈만 지지하는 내용을 낮은 확정성으로 표시한다.
7. **7일 관찰 실험**: 사용자가 실제 생활에서 확인할 작고 비의료적인 행동을 제안한다.
8. **근거 지도 전체 보기**: 각 문장의 출처, 반대 신호, 도구 버전, 한계를 공개한다.

### 11.1 주요 화면 상태

- 결과 없음: 분석을 강요하지 않고 과학 평가부터 시작할 수 있는 목적별 선택지를 제공한다.
- 1개 완료: 결과가 단일 관점임을 알리고 비교 가능한 다음 평가를 제안한다.
- 2개 완료: 일치·차이를 미리 보여 주지 않고 잠금 해제까지 필요한 관점 하나를 설명한다.
- 3개 이상이나 과학 평가 1개: 문화적 결과 수와 과학적 근거 수를 분리해 표시한다.
- 잠금 해제: 즉시 리포트를 생성하고 사용자가 특정 결과를 제외해 다시 볼 수 있게 한다.
- 버전 불일치: 어떤 결과가 오래되었는지 표시하고 재검사 또는 이전 규칙으로 보기 중 안전한 선택을 제공한다.
- 저장소 차단: 현재 세션에서만 보고서를 만들고 내보내기를 제안한다.

### 11.2 플랫폼 전체 연결

- 홈 `SelfAtlas`에 고정 검사 개수가 아닌 현재 포함 결과 수와 통합 리포트 CTA를 추가한다.
- 개별 결과 화면 하단은 `핵심 결과 / 근거와 한계 / 자기초상에 추가 / 다음 탐색` 구조로 맞춘다.
- `NextLens`는 부족한 과학적 관점을 우선 제안하되 특정 분석을 강제하지 않는다.
- 홈과 결과 화면에서 과학, 문화, 상황, 관계의 라벨 체계를 동일하게 쓴다.
- 결과를 저장하지 않은 사용자에게 통합 기능을 사용하려고 개인정보 저장을 강요하지 않는다.

## 12. 레이어 조합형 캐릭터

캐릭터는 다음 로컬 레이어로 구성한다.

- 중립 실루엣과 자세
- 먹빛·한지 배경과 조명
- 비민감 색 팔레트
- 추상 상징과 소도구
- 장식 모션과 정지 대체 이미지

레이어 조합은 정렬된 스냅샷 ID, 종합 규칙 버전, 사용자가 선택한 표현 스타일을 해시한 seed로 결정한다. 같은 입력과 스타일은 같은 결과를 만들고, 스타일을 바꿔도 종합 주장 자체는 바뀌지 않는다.

금지 사항은 다음과 같다.

- 인종, 성별, 나이, 장애, 종교, 건강 상태 추론
- 특정 표정이나 신체 특징을 병리·도덕성·지능과 연결
- 문화적 상징을 과학적 근거 강도로 표현
- 이미지 안에 결과 텍스트를 넣어 접근성이나 번역을 막는 방식
- 깜박임, 자동 반복 강제, 감소 모션 설정 무시

이미지에는 의미 있는 대체 텍스트를 제공하고 장식 레이어는 보조기술에서 숨긴다. 에셋 manifest는 경로, 크기, 비율, 대체 텍스트, 레이어 역할, 버전을 관리한다.

## 13. 시각 디자인 개선 원칙

기존 LUMINA의 먹빛, 한지, 오행 계열 정체성을 유지한다. 새 기능 때문에 일반적인 유리 효과 대시보드로 바꾸지 않는다.

- 한 화면에는 캐릭터, 핵심 주장, 근거 지도 중 하나만 주인공으로 둔다.
- 캐릭터와 한 줄 통찰을 먼저 보여 주고 상세 수치와 출처는 점진적으로 펼친다.
- 과학적 관찰은 녹회색, 상징적 관점은 금갈색 계열을 쓰되 텍스트와 아이콘을 함께 제공한다.
- 본문 대비와 여백을 장식보다 우선하고 작은 라벨 아래에는 쉬운 설명을 붙인다.
- 핵심 본문은 서버에서 보이는 상태로 렌더링하고 저장소 접근, 필터, 캐릭터 모션만 작은 Client Component로 격리한다.
- 필수 콘텐츠를 초기 `opacity: 0` 상태로 두지 않는다.
- `prefers-reduced-motion`, 키보드 초점, 200% 확대, 고대비, 모바일 가로 넘침, 이미지 실패 대체를 필수 조건으로 둔다.
- 첫 모바일 뷰의 캐릭터 이미지 예산은 기준선 측정 뒤 문서화하며, 기존 페이지 대비 LCP와 초기 전송량을 악화시키지 않는다.

## 14. 오류 처리

| 상황 | 사용자 표시 | 시스템 동작 |
|---|---|---|
| 스냅샷 스키마 오류 | 해당 결과를 사용할 수 없고 다시 열어야 함 | 오류 결과만 격리하고 나머지 결과로 계속 |
| 도구 버전 불일치 | 최신 해석과 직접 비교할 수 없음 | 자동 변환하지 않고 재검사 안내 |
| 비교 규칙 없음 | 서로 다른 관점이라 직접 연결하지 않음 | `not-comparable`로 유지 |
| 종합 주장이 0개 | 결과가 부족하거나 비교 범위가 좁음 | 단일 결과 요약과 다음 탐색만 제공 |
| IndexedDB 차단·용량 부족 | 이번 세션에서만 사용 가능 | 메모리 전용 모드, 내보내기 제안 |
| 캐릭터 에셋 누락 | 기본 먹빛 초상 표시 | 해석 텍스트와 근거는 정상 유지 |
| 후속 AI 실패 | 기본 문장으로 표시됨 | 결정론적 템플릿으로 즉시 대체 |

오류는 결과의 의미를 바꾸거나 조용히 누락하지 않는다. 사용자에게 영향, 제외된 결과, 복구 행동을 함께 알린다.

## 15. 개인정보와 분석 이벤트

MVP는 다음을 지킨다.

- 원문 응답, 자유서술, 출생 정보, 관계 상대 정보는 IndexedDB, URL, 로그, 분석 이벤트에 기록하지 않는다.
- 분석 내용을 이벤트 이름이나 속성으로 보내지 않는다.
- 사용자가 동의한 경우에만 `integrated_report_opened`, `evidence_expanded`, `experiment_saved` 같은 비식별 기능 이벤트를 보낸다.
- 캐릭터 조합 seed와 결과 스냅샷은 외부 이미지 서비스로 보내지 않는다.
- 내보내기 전에 포함 필드와 로컬 파일 취급 주의를 설명한다.

선택 동기화는 별도 명세에서 사용자별 소유권, RLS, 철회, 삭제, 보존 기간, 백업 삭제 범위를 검증한 뒤에만 진행한다. 마이그레이션은 별도 사람 승인 전 실행하지 않는다.

## 16. 검증 전략

### 16.1 도메인 단위·속성 테스트

- 같은 결과 집합은 입력 순서가 달라도 같은 claim ID와 등급을 만든다.
- 같은 분석의 재검사가 잠금 해제 방법 수를 부풀리지 않는다.
- `not-comparable` 관계에서 교차 주장이 생성되지 않는다.
- 과학적 점수와 문화적 결과가 한 수치로 합산되지 않는다.
- 모든 claim에 한 개 이상의 출처와 한계 목록이 있다.
- `tension` claim은 반대 신호와 맥락 질문을 가진다.
- 규칙 버전이 바뀌면 기존 보고서가 재계산 필요 상태가 된다.
- 같은 입력과 스타일 seed는 같은 캐릭터 recipe를 만든다.

### 16.2 계약·개인정보 테스트

- 과학 평가 6종과 안정적 문화 해석 3종의 기존 결과 fixture를 개인정보 없는 스냅샷으로 변환하고 왕복 직렬화를 검증한다.
- 저장 객체에서 응답 키, 질문 문장, 이름, 이메일, 출생 필드를 금지한다.
- 손상된 JSON, 오래된 스키마, 알 수 없는 구성개념을 안전하게 거부한다.
- 콘솔, URL, 분석 이벤트 payload에 파생 결과 내용이 나타나지 않는지 검사한다.

### 16.3 내용 검토

- 심리측정 전문 검토자가 구성개념 레지스트리와 비교 관계마다 출처와 해석 범위를 확인한다.
- 고정 fixture에 대해 전문가가 기대 claim, 금지 claim, 허용 행동 실험을 작성한다.
- 전문가 승인을 받지 않은 비교 관계는 운영 레지스트리로 승격하지 않는다.
- 사용자 이해도 테스트에서 과학적 관찰과 상징적 관점, 지지됨과 탐색적을 구분할 수 있는지 확인한다.

### 16.4 UI·접근성·성능 테스트

- Playwright로 결과 0개, 1개, 2개, 잠금 해제, 결과 제외, 전체 삭제, 저장소 차단 흐름을 검증한다.
- axe, 키보드, 스크린리더 이름, 감소 모션, 200% 확대를 검증한다.
- 390px, 768px, 1440px에서 가로 넘침과 정보 순서를 확인한다.
- 캐릭터 이미지 실패와 JavaScript 비활성 또는 지연 상황에서도 핵심 문장과 근거 설명이 보이는지 확인한다.
- 구현 전후 Core Web Vitals와 초기 이미지·JavaScript 전송량을 같은 조건에서 비교하고 회귀를 허용하지 않는다.

## 17. 구현 작업 분해와 순서

이번 명세의 다음 구현 계획은 아래 **로컬 우선 MVP**만 상세 작업으로 나눈다.

| 단계 | 결과물 | 선행 조건 |
|---|---|---|
| 0. 기준선과 레지스트리 | 분석 층, 구성개념, 비교 관계, 버전, 한계 | 없음 |
| 1. 결과 스냅샷 | 과학 평가 6종과 안정적 문화 해석 3종의 안전한 파생 요약 어댑터와 계약 테스트 | 단계 0 |
| 2. 근거 그래프 | 비교 판정, claim 규칙, 결정론적 카피 | 단계 0~1 |
| 3. 로컬 보관함 | IndexedDB 저장소, 제외·삭제·내보내기 | 단계 1 |
| 4. 통합 UI | 라우트, 상태별 화면, 홈·결과·NextLens 연결 | 단계 2~3 |
| 5. 캐릭터 | 로컬 에셋 manifest와 recipe, 접근성 대체 | 단계 2, UI 골격 |
| 6. 파일럿 | 고정 fixture, 전문가 검토, Preview 이해도 검증 | 단계 0~5 |

예상 기간은 1명의 풀타임 개발 기준 4~6주다. 전문가 내용 검토와 신규 시각 에셋 제작 일정은 병렬로 진행할 수 있으나, 검토되지 않은 규칙과 에셋은 운영 공개 조건을 충족하지 못한다.

후속 프로젝트는 다음 순서로 분리한다.

1. **제한형 AI 문장화 명세**: 모델, 전송 동의, JSON 검증, 비용·지연·실패 대체.
2. **계정 동기화와 RLS 명세**: 인증 주체, 테이블, 정책, 삭제·철회, 스테이징 마이그레이션.
3. **관계 초상 명세**: 두 사람의 동의와 관계 데이터 소유권을 포함한 별도 모델.

## 18. 공개 조건

다음 조건을 모두 충족해야 기능 플래그를 운영에 연다.

1. 과학 평가 6종과 안정적 문화 해석 3종 어댑터의 계약·개인정보 테스트가 모두 통과한다.
2. 비교 가능한 관계마다 근거 자료와 전문가 검토 기록이 있다.
3. 서로 다른 척도 수치 합산과 과학·문화 확신도 혼합이 0건이다.
4. 모든 통합 주장에 출처, 한계, 등급이 표시된다.
5. AI, 계정, 서버 데이터베이스 없이 전체 핵심 흐름이 작동한다.
6. 사용자가 결과별 제외, 전체 삭제, 내보내기를 직접 수행할 수 있다.
7. 접근성, 모바일, 이미지 실패, 저장소 차단 흐름이 통과한다.
8. Preview 사용자에게 과학적 결과와 상징적 렌즈의 차이가 오해 없이 전달된다.
9. 기존 개별 분석 흐름과 홈의 완료 기록에 회귀가 없다.

## 19. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 다른 척도를 같은 특성처럼 과잉 연결 | 등록된 비교 관계 외 연결 금지, 전문가 승인 게이트 |
| 문화 해석이 과학 결과처럼 보임 | 별도 층·색·아이콘·라벨, 과학 등급 계산에서 제외 |
| 긴장이 부정적 모순처럼 전달됨 | 맥락 의존 등급과 상황 질문, 반대 신호 공개 |
| 캐릭터가 사람을 고정 유형화함 | 갱신 가능 표시, 유형명 금지, 해석과 스타일 seed 분리 |
| 로컬 저장이 완전한 보안으로 오해됨 | 공용 기기 경고, 저장 안 함, 삭제·내보내기 제공 |
| 규칙 변경으로 결과가 조용히 달라짐 | 규칙 버전 고정, 재계산 필요 상태, 변경 설명 |
| 외부 AI가 새 사실을 만들어 냄 | MVP에서 제외, 후속 allowlist·schema·fallback 게이트 |
| 기능 범위가 한 번에 커짐 | MVP, AI, 동기화, 관계 초상을 별도 명세와 출시로 분리 |

## 21. 승인 결정 요약

1. 제품 형태: 근거 분리형 통합 자기초상과 재미 요소로서의 캐릭터.
2. 잠금 해제: 서로 다른 개인 분석 3개, 서로 다른 과학 평가 2개 이상.
3. 저장: 로컬 우선 파생 요약, 선택 동기화는 후속.
4. 종합: 근거 그래프가 결론을 확정하는 검증형 하이브리드.
5. 캐릭터: 로컬 레이어 조합형, 민감 특성 추론 금지.
6. 첫 화면: 살아 있는 자기 초상 구조.
7. 구현 범위: 로컬 우선 MVP를 먼저 완결하고 AI·동기화·관계 초상은 분리.

# `@engine/*` — 계산 엔진

순수 함수 라이브러리. **계산과 해석을 엄격히 분리한다.**
엔진은 결정론적 구조화 JSON만 만들고, 문장 생성은 해석 레이어가 그 JSON을 입력으로 받아 수행한다.

- React·Next.js·DOM에 의존하지 않는다. 서버·클라이언트·테스트 어디서든 동일하게 돈다.
- 엔진 내부에서 **현재 시각을 읽지 않는다**. 시간 의존 결과가 필요하면 호출부가 `referenceDate`를 넘긴다.
  공유 링크가 몇 달 뒤에 열려도 같은 결과가 나와야 하기 때문이다.
- 모든 반환값은 `Object.freeze` 되어 하위 소비자가 변형할 수 없다.

```
shared/    엔진 공통 — 출생 입력 검증, 타임존/진태양시, 3계층 신뢰도 태깅
saju/      사주팔자 (계층 2: 문화적 해석)
astro/     서양 점성술 — 행성 위치·하우스·주요 각 (계층 2)
horoscope/ 날짜별 하늘·일진 신호를 근거로 한 문화적 리딩 (계층 2)
tarot/     결정론적 셔플·스프레드·정역방향 (계층 2)
numerology/ 생애수·운명수 산술 (계층 2)
psychometrics/ IPIP-50 응답 채점·신뢰도 계산 (계층 1의 척도 계산)
characters/ 오행 분포를 화면용 캐릭터 정의에 연결하는 데이터 계층
synastry/  두 사주 프로필의 지지 합·충·삼합과 천간 오행 방향 비교 (계층 2)
```

## 1. 3계층 신뢰도 (`shared/tier.ts`)

모든 엔진 결과는 `tier` 필드를 갖는다.

| 계층 | 값 | 고지문 | 해당 엔진 |
|---|---|---|---|
| 과학적 검증 | `scientific` | 불필요 | Big Five 등 |
| 문화적 해석 | `cultural` | **필수** | 사주, 점성술, 타로 |
| 엔터테인먼트 | `entertainment` | **필수** | 레거시 문장 은행 API만 유지 |

`requiresDisclaimer(tier)`가 `true`면 UI는 반드시 고지문을 함께 렌더링한다.
계층이 다른 결과를 **가중 평균으로 합성하지 않는다** — 인식론적으로 다른 체계이므로 병렬 표기한다.

현재 공개 운세 화면은 실제 하늘 위치·일진·지지 관계에서 신호를 만들고 `cultural`로 표시한다.
선택된 문장마다 `evidenceId`가 있으며, 화면의 근거 표가 이를 함께 보여 준다. 프로필이 있는
비공개 운세 화면에서는 출생 천체와 현재 천체의 도수 각도 추가한다.

## 2. `@engine/saju` — 사주팔자

### 2.1 핵심 설계 결정

**사주의 네 기둥은 음력을 쓰지 않는다.** 흔한 오해라 명시해 둔다.

| 기둥 | 근거 | 구현 |
|---|---|---|
| 연주 | 입춘(태양 황경 315°) | 천문 계산 |
| 월주 | 12개 절(節), 15° 간격 | 천문 계산 |
| 일주 | 율리우스 적일(JDN) 기반 60갑자 | 순수 산술 |
| 시주 | 일간 + 진태양시 시각 | 순수 산술 |

음력은 (1) 사용자가 음력 생일을 입력했을 때의 변환, (2) 결과 화면의 음력 표기에만 쓰인다.

결과 뷰는 십신 10종·십이운성 12종·대운·세운을 구조화해 반환한다. 문장 해석은 `messages/`
카탈로그와 서버 컴포넌트가 담당하며, 병·사 같은 십이운성 명칭을 건강·수명 예측으로 읽지 않도록
화면에서 한계를 함께 고지한다.

### 2.2 절기 — 표 대신 천문 계산

절기는 태양의 겉보기 황경이 15°의 배수를 지나는 **절대 시각**이다. 지역 달력이나 변환표에
의존하지 않으므로, `astronomy-engine`의 `SearchSunLongitude`로 직접 구한다.

- 2024년 입춘 = `2024-02-04 17:26:49 KST`
- 2023년 동지 = `2023-12-22 12:27:34 KST`

공개 자료는 분 단위로만 표기하고 초 자리 처리(버림/반올림)가 자료마다 다르므로,
테스트는 계산값을 초 단위로 고정하고 공개 표기와의 1분 이내 일치만 확인한다.

### 2.3 진태양시 (`shared/time.ts`)

두 가지 보정을 적용한다.

1. **경도 보정** — 표준자오선과 출생지 경도의 차이를 4분/도로 환산. 서울(126.978°E)은 약 −32.1분.
2. **균시차** — 그리니치 겉보기 항성시와 태양 겉보기 적경에서 직접 유도. 범위 −14.2 ~ +16.5분.

표준자오선을 하드코딩하지 않고 **해당 시점의 실제 UTC 오프셋에서 역산**한다. 덕분에 아래가 자동으로 처리된다.

| 기간 | 한국 오프셋 | 실효 표준자오선 |
|---|---|---|
| ~1954 | UTC+9 | 135°E |
| 1954–1961 | UTC+8:30 | 127.5°E |
| 1955–1960 여름 | UTC+9:30 (서머타임) | 142.5°E |
| 1987–1988 여름 | UTC+10 (서머타임) | 150°E |
| 1962~ | UTC+9 | 135°E |

표준시 이력은 IANA tz 데이터베이스(luxon 경유)에 전적으로 위임한다. 직접 하드코딩하지 않는다.

### 2.4 두 개의 학설을 옵션으로 노출

명리 유파마다 갈리는 지점은 **임의로 하나를 고르지 않고 옵션으로 노출하고 기본값을 문서화**한다.

| 옵션 | 기본값 | 의미 |
|---|---|---|
| `dayBoundaryRule` | `"zi23"` | 야자시론 — 23:00에 일주가 바뀐다. 국내 실무 다수설. |
| | `"midnight"` | 자정론 — 00:00에 바뀌고, 23:00~23:59는 당일 일간 + 子시(조자시법). |
| `applyTrueSolarTime` | `true` | 진태양시 보정 적용 |
| `applyEquationOfTime` | `true` | 균시차만 따로 끌 수 있다 |

두 학설은 **23:00~23:59 출생에서만** 갈린다. 그 구간이면 `boundary.inLateZiHour`가 `true`가 되므로
UI는 이때 "학설에 따라 결과가 갈릴 수 있음"을 고지해야 한다.

### 2.5 십신 판정 기준

지지의 십신은 **지장간 정기(正氣)** 로 판정한다. 자·오·사·해는 자리의 음양과 본질의 음양이
어긋나기 때문이다(체용 반전).

> 갑(甲) 일간 기준 자(子) → 子의 정기는 계(癸, 음수) → **정인** (편인이 아님)

### 2.6 결정론성

`computeSaju(input, options)`는 같은 입력에 대해 항상 같은 JSON을 낸다.
`options.referenceDate`를 주지 않으면 나이·현재 대운·세운(`result.current`)을 아예 만들지 않는다.
공유 링크·PDF의 재현성을 위한 의도적 설계다.

### 교차검증 (품질 게이트)

`__tests__/crossValidation.test.ts`가 **436건**을 독립 구현체 [`lunar-javascript`](https://github.com/6tail/lunar-javascript)와 대조한다.
오라클은 寿星天文历 계보의 별개 코드베이스이므로 자기참조가 아니다.

| 케이스 종류 | 건수 | 노리는 것 |
|---|---|---|
| 무작위 (1901–2099) | 120 | 전 구간 일반 정확도 |
| 절입 경계 | 240 | 5년 × 12절 × (±10분, ±3시간) |
| 자시 경계 | 64 | 8일 × (22:59 ~ 01:00) |
| 달력 경계 | 12 | 윤년 2/29, 연말연시, 월말 |

정렬 조건: 오라클은 UTC+8 고정·진태양시 미보정·sect 1(야자시론)을 전제하므로,
케이스를 `Etc/GMT-8`에 두고 `applyTrueSolarTime: false`, `dayBoundaryRule: "zi23"`으로 맞춘다.

절기 절입 시각 자체는 8개 연도 × 24절기를 90초 이내 오차로 별도 대조한다.

## 4. 나머지 엔진

### `@engine/astro`

`astronomy-engine`으로 지심 겉보기 황경과 진분점 기준을 계산하고, 10천체·홀사인/이퀄 하우스·
주요 5각을 구조화한다. `astronomia` 독립 오라클과의 교차검증은 0.05° 게이트로 유지한다.

### `@engine/horoscope`

`computeDailyReading`은 날짜와 선택한 체계만으로 UTC 정오 하늘을 만들고, 띠 페이지에는 일진·
지지 관계를, 별자리 페이지에는 행성 위치·주요 각·역행 여부를 신호로 넣는다. 난수는 공개 리딩의
의미를 고르지 않는다. 프로필 경로는 `timeZone`과 출생 천체를 추가 인자로 받아 도수 기반 트랜싯을
계산한다. `phrases.ts`와 `computeDailyHoroscope`는 하위 호환용 레거시 API다.

### `@engine/tarot`

78장(메이저 22 + 마이너 56)과 스프레드 정의를 이용해 시드 기반 셔플을 수행한다. 같은
`(spread, seed)`는 카드·자리·정역방향을 재현하며, 문장 대신 카드의 ko/en 키워드와 자리별 성찰
질문을 반환한다.

### `@engine/numerology`

양력 생년월일의 숫자 합을 생애수로 줄이고, 선택한 로마자 이름을 피타고라스 문자값으로 합산해
운명수를 낸다. 11·22·33은 마스터 넘버로 보존한다.

### `@engine/psychometrics`

IPIP-50의 역문항을 포함한 5요인 점수와 척도 내 위치를 계산한다. 공개 원자료에서 산출한
집단 규준(연령·성별 층화 자료가 없어 전체 집단 규준만 제공), T점수·백분위·측정표준오차와
신뢰구간을 결과에 함께 표시한다. `reliability.ts`의 Cronbach's α 계산기는 빌드 스크립트가
원자료 요약값을 교차검증할 때 사용하며, 개인 1명의 응답으로 α를 계산하거나 지어내지 않는다.

### `@engine/characters`

오행 분포에서 선택된 캐릭터 정의와 ko/en 이름·태그라인을 제공한다. 해석 문장 자체를 만들지
않아 엔진의 순수 함수 계약을 지킨다.

## 5. 의존성

| 패키지 | 용도 | 비고 |
|---|---|---|
| `astronomy-engine` | 절기, 균시차, 행성 위치 | 데이터 파일 불필요, 오프라인 |
| `korean-lunar-calendar` | 한국 음력 ↔ 양력 | 중국 농력(UTC+8)이 아닌 **한국 음력(UTC+9)** 기준. 1000–2050년 |
| `luxon` | IANA 타임존, 역사적 표준시 | |
| `tz-lookup` | 좌표 → 타임존 | 오프라인 |
| `lunar-javascript` | **테스트 오라클 전용** (devDependency) | 프로덕션 번들에 들어가지 않는다 |

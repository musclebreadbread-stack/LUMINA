# LUMINA 신뢰도 우선 플랫폼 고도화 설계

> 작성일: 2026-08-24
>
> 상태: 대화 설계 승인 완료, 문서 검토 대기
>
> 기준 가치: 신뢰도 + 자기이해
>
> 범위: 프로그램 수준 설계. 첫 구현 계획은 Phase 0만 다룬다.

## 1. 목적

LUMINA의 다음 단계는 분석 기능의 수를 단순히 늘리는 것이 아니다. 기존 계산 엔진과 고유한 시각 정체성을 보존하면서, 사용자가 각 결과의 근거·적용 범위·한계를 이해하고 스스로를 탐색할 수 있는 플랫폼으로 고도화한다.

이 설계는 다음 네 가지 목표를 함께 달성한다.

1. 기존 분석의 근거 표시와 개인정보 흐름을 정직하게 바로잡는다.
2. 결과를 핵심 요약부터 방법론까지 점진적으로 깊게 탐색할 수 있게 한다.
3. 첫 신규 분석으로 O*NET Interest Profiler 기반 RIASEC 직업 흥미 지도를 준비한다.
4. 이미지·모션·홈 탐색 구조를 모바일 친화적이고 전문적인 경험으로 통합한다.

과학적 타당성은 코드 완성만으로 선언하지 않는다. 라이선스 검토, 번역·적응, 인지 인터뷰, 표본 설계, 측정 속성 분석, 외부 전문가 검토가 끝나기 전까지 해당 분석은 검증 상태를 그대로 노출한다.

## 2. 설계 원칙

### 2.1 근거의 종류를 섞지 않는다

- 심리측정 결과는 신뢰도, 측정오차, 규준 모집단, 타당화 상태를 제시한다.
- 사주·점성술의 천문 계산은 계산 재현성과 알고리즘 버전을 제시한다.
- 사주·타로·수비학의 해석은 역사적 출처와 적용한 해석 규칙을 제시한다.
- 문화적·상징적 분석에 백분위나 과학적 확률처럼 보이는 수치를 붙이지 않는다.
- 어떤 분석도 의료·정신건강 진단, 채용 판정, 미래 보장으로 표현하지 않는다.

### 2.2 결과보다 결과가 만들어진 경로를 함께 보여 준다

결론만 길게 쓰는 대신 입력 → 계산·채점 → 근거 → 해석 → 한계의 추적 경로를 제공한다. 사용자는 기본 화면에서 핵심만 읽고, 원할 때 세부 점수와 출처를 펼친다.

### 2.3 개인 결과는 기본적으로 로컬에 머문다

- 개인 입력과 설문 원응답을 URL, 서버 로그, referrer에 넣지 않는다.
- 기본 세션에서는 파생 결과만 브라우저 세션 저장소에 보관한다.
- 장기 보관은 사용자가 명시적으로 선택한 경우에만 브라우저 로컬 저장소를 사용한다.
- 외부 공유는 별도 동작이며, 공유되는 항목을 먼저 보여 주고 동의를 받는다.

### 2.4 서버 컴포넌트를 기본으로 유지한다

공개 랜딩, 방법론, 참고문헌, 정적 설명은 Server Component로 유지한다. 설문 상태, 로컬 결과 로딩, 차트 상호작용, 애니메이션만 작은 Client Component 경계에 둔다. 클라이언트에 비밀키나 `service_role`을 포함하지 않는다.

### 2.5 기존 정체성을 버리지 않는다

먹빛·한지·황금색의 `living fate atlas` 정체성은 유지한다. 다만 긴 글은 밝고 안정된 콘텐츠 표면에서 읽게 하고, 장식은 선택·상태·구조를 설명하는 데만 사용한다.

### 포함

- 근거 메타데이터와 분석 카탈로그의 단일 출처
- 모든 분석의 고지·출처·검증 상태 표시
- 애착, 다크 트라이어드, 융 유형의 과장된 주장 교정
- 개인 입력과 원응답의 URL 제거

- 홈 정보구조, 결과 UX, 이미지·모션·성능 개선
- 선택형 Supabase 동기화를 위한 경계와 RLS 원칙

### 제외

- 의료·정신질환 선별 검사
- 채용·교육 배치·보험 판단용 점수

- Phase 0에서의 Supabase 도입
- 승인 없는 파일 삭제, 마이그레이션 실행, 배포, 외부 데이터 전송

## 6. 근거 모델

기존 `scientific | cultural | entertainment` 값은 화면 분위기와 호환성을 위해 당분간 유지할 수 있지만, 신뢰 주장의 단일 근거로 사용하지 않는다. 다음 메타데이터를 분석별로 추가한다.

```ts
type MethodCategory =
  | "psychometric"
  | "astronomical-calculation"
  | "traditional-symbolic"
  | "derived-exploratory";

type ValidationStatus =
  | "validated-target-population"
  | "validated-other-population"
  | "translation-not-validated"
  | "derived"
  | "experimental";

type LicenseStatus =
  | "verified"
  | "permission-required"
  | "not-approved";

interface EvidenceProfile {
  readonly methodCategory: MethodCategory;
  readonly validationStatus: ValidationStatus;
  readonly targetPopulation: string;
  readonly normSource: string | null;
  readonly instrumentVersion: string;
  readonly licenseStatus: LicenseStatus;
  readonly lastReviewed: string;
  readonly limitations: readonly string[];
  readonly referenceIds: readonly string[];
}
```

모든 공개 분석은 다음 정보를 가진다.

- `methodKey`, 경로, 이름, 목적군, 소요시간, 문항 수
- `EvidenceProfile`
- 결과에서 허용되는 주장과 금지되는 주장
- 고지문, 버전, 변경 기록
- 한국어·영어 메시지 키와 참고문헌 그룹

카탈로그는 홈 카드, 만다라, 방법론, 참고문헌, 사이트맵 대상, 결과 뱃지를 함께 생성한다. 목록을 여러 파일에 하드코딩하지 않는다. 누락된 라이선스 상태나 참고문헌 ID가 있으면 테스트와 빌드에서 실패시킨다.

과학적 계층도 반드시 한계 고지를 표시한다. 현재 `requiresDisclaimer("scientific") === false`인 흐름은 폐기하고, 분석별 `EvidenceProfile.limitations`와 일반 비진단 고지를 함께 렌더링한다.

## 7. Phase 0 상세 설계

### 7.1 분석별 즉시 상태

| 분석 | Phase 0 표시 | 즉시 제거할 주장 | 후속 조건 |
|---|---|---|---|
| Big Five IPIP-50 | 타 모집단 타당화·한국어 적응 미완료 | 한국인 규준처럼 보이는 표현 | 한국어 인지 인터뷰·파일럿 |
| 융 유형 렌즈 | 파생·탐색적 | 공식 MBTI 검사, 독립 과학검사처럼 보이는 표현 | Big Five 파생 규칙·한계 공개 |
| 애착 | 실험적, 신규 응답 전 경고 | ECR-R 정식 구현, 경험적 백분위 주장 | 정식 문항·7점 척도·허가·한국어 타당화 |
| 다크 트라이어드 | 번역 미타당화 | 한국어 3요인 구조가 검증됐다는 표현 | 한국 타당화 구조와 문항 사용 권한 확인 |
| 사주·점성술 | 계산 + 전통 해석 | 과학적 미래 예측 암시 | 계산 버전·유파·해석 규칙 공개 |
| 타로·수비학·운세 | 전통·상징 | 통계적 예측 확률 암시 | 역사·상징 출처와 생성 규칙 공개 |
| 궁합 | 적용 분석별 혼합 | 단일 점수가 관계 성공을 예측한다는 표현 | 신호별 근거와 조정 가능성 표시 |

애착의 현재 정규분포 기반 백분위는 결과에서 제거한다. 다크 트라이어드와 융 유형은 기능을 숨기기보다 검증 상태와 한계를 첫 화면에 명시하되, 사용 허가에 문제가 발견되면 신규 응답을 중단한다.

### 7.2 개인정보 흐름

현재 URL에는 설문 원응답뿐 아니라 생년월일, 출생 시각, 위치, 성별, 수비학 이름이 포함될 수 있다. 압축·인코딩은 암호화가 아니며 서버 요청 경로에 포함되면 서버에 전송된 것이다.

새 기본 흐름은 다음과 같다.

```text
Client 입력 상태
  → 순수 엔진으로 계산
    → 파생 결과 AssessmentRunV1 생성
      → sessionStorage에 random UUID 키로 저장
        → /<method>/result?run=<opaque-id>
          → Server 결과 셸 + Client ResultRunLoader
```

`AssessmentRunV1`에는 원응답을 넣지 않는다.

```ts
interface AssessmentRunV1<TMethod extends string, TSummary> {
  readonly schemaVersion: 1;
  readonly id: string;
  readonly methodKey: TMethod;
  readonly instrumentVersion: string;
  readonly locale: "ko" | "en";
  readonly createdAt: string;
  readonly scoreSummary: TSummary;
}
```

- 원응답은 제출 순간까지 React 상태에만 존재한다.
- 기본 저장은 `sessionStorage`이며 탭 세션 종료 시 사라진다.
- 사용자가 `이 브라우저에 기록 저장`을 선택하면 파생 결과만 `localStorage`에 복사한다.
- 결과 URL의 UUID는 같은 브라우저의 저장값 없이는 의미가 없다.
- 결과 페이지는 `noindex`를 유지한다.
- 유효기간 만료, 저장소 차단, 잘못된 버전이면 복구 안내와 다시 시작 버튼을 제공한다.

외부 공유는 Phase 0에서 정적 공유 카드와 텍스트 요약만 제공한다. 원응답이나 출생 입력을 포함하는 재현 링크는 만들지 않는다. 향후 대화형 공유 링크가 필요하면 별도 위협 모델과 명시적 동의 화면을 먼저 설계한다.

### 7.3 Phase 0 완료 조건

- 설문 원응답, 이름, 생년월일, 출생 시각, 위치, 성별을 기본 결과 URL에 넣지 않는다.
- 홈·방법론·참고문헌·결과의 분석 목록이 같은 카탈로그를 사용한다.
- 모든 분석에 검증 상태, 모집단, 버전, 한계가 표시된다.
- 애착 결과에 가정으로 만든 백분위가 없다.
- `MBTI 유형 검사` 대신 `융 유형 렌즈(비공식)`를 사용한다.
- 한국어 다크 트라이어드에 번역·요인구조 한계를 표시한다.
- 개인정보 처리방침이 실제 데이터 흐름과 일치한다.
- 타입 검사, 린트, 단위 테스트, 빌드, 관련 E2E가 통과한다.

## 8. 공통 결과 체계

모든 결과는 다섯 층으로 구성한다.

1. **핵심 요약** — 사용자가 30초 안에 이해할 수 있는 3~5개 핵심 문장
2. **점수와 구조** — 척도별 점수, 상호작용, 측정 가능한 경우에만 불확실성
3. **상세 해석** — 맥락, 강점, 긴장, 반대 조건을 함께 설명
4. **실천과 성찰** — 작은 행동 제안과 비판적 자기성찰 질문
5. **방법과 한계** — 채점법, 버전, 모집단, 출처, 라이선스, 한계

공통 구성요소는 개인 결과 데이터와 정적 근거 데이터를 분리한다.

- Server Component: 결과 표지의 일반 설명, 방법론, 출처, 한계
- Client Component: 로컬 실행 불러오기, 개인 점수 차트, 탭·펼침 상태
- 순수 엔진: 계산과 채점만 담당하고 번역·브라우저 저장소를 참조하지 않음
- 결과 모델: 엔진 출력과 번역 키를 화면 구성으로 변환

오류 메시지는 장식보다 복구 행동을 먼저 보여 준다. 유효하지 않은 실행, 버전 불일치, 누락된 로컬 데이터, 계산 실패를 구분하고 각각 다시 검사, 기록 목록, 홈 이동 중 적절한 행동을 제시한다.

## 9. 기존 분석 심층화

### 9.1 Big Five

- 현 IPIP-50을 `빠른 검사`로 유지한다.
- 규준 표본, T점수, 백분위, SEM·신뢰구간을 같은 맥락에서 설명한다.
- 한국어 번역과 영어권 온라인 규준의 한계를 결과 첫 층과 방법론에 모두 표시한다.
- 120문항·30 facet 트랙은 한국어 적응 파일럿 이후 별도 기능으로 출시한다.
- 재검사 비교는 점수 변화가 신뢰구간을 넘는지와 함께 보여 준다.

### 9.2 애착

- 정식 ECR-R을 사용할 경우 공식 36문항, 7점 척도, 축별 역채점 규칙을 따른다.
- 한국어 단축형을 선택할 경우 해당 척도의 문항·요인·규준을 혼합하지 않는다.
- 불안과 회피의 연속 점수를 기본 결과로 하고 유형 분류는 보조 설명으로 둔다.
- 임의 중간값으로 유형이나 백분위를 만들지 않는다.

### 9.3 다크 트라이어드

- 한국어 서비스에서 3요인 원형을 유지할지 한국 연구의 2요인 단축 구조를 사용할지 사용 권한과 타당화 자료로 결정한다.
- 문항과 결과 카피는 낙인, 범죄성, 인격 진단을 암시하지 않는다.
- 규준의 표본·언어·수집 경로를 결과와 함께 공개한다.

### 9.4 융 유형 렌즈

- Big Five에서 파생된 비공식 표현임을 제목에서부터 명시한다.
- Big Five 원점수와 4축 변환 결과를 시각적으로 분리한다.
- 경계값에 가까운 축은 단정적 한 글자 대신 경계 상태를 표시한다.
- 공식 MBTI 상표·문항·규준과 무관하다는 고지를 유지한다.

### 9.5 전통·상징 분석

- 사주·점성술은 계산 입력, 시간대, 역법·하우스 체계, 엔진 버전을 추적 가능하게 한다.
- 타로는 카드별 도상, 전통적 의미, 질문 맥락, 배열 생성 규칙을 보여 준다.
- 수비학은 계산식과 현대 수비학의 역사적 성립을 분리한다.
- 궁합은 단일 총점보다 일치 신호, 긴장 신호, 조정 질문을 보여 준다.

## 10. RIASEC 직업 흥미 지도

### 10.1 제품 결정

첫 제품판은 **O*NET Interest Profiler Short Form 60문항**을 기준으로 한다. O*NET은 시간 제약이 있는 모바일 환경에는 30문항 Mini-IP를 제공하지만 가능한 경우 60문항판을 권장한다. LUMINA의 우선 가치가 속도보다 신뢰도이므로 60문항을 선택한다. 30문항판은 후속 빠른 검사로 검토한다.

결과는 Realistic, Investigative, Artistic, Social, Enterprising, Conventional 여섯 흥미 영역과 상위 조합을 제공한다. 흥미는 능력, 성과, 취업 가능성, 직업 적합 판정과 동일시하지 않는다.

### 10.2 출시 게이트

다음 조건이 모두 충족되기 전에는 공개 프로덕션 분석으로 표시하지 않는다.

1. O*NET Tools Developer License 또는 적용 가능한 사용 조건 확인
2. 문항·응답척도·채점 규칙의 변경 범위 확정
3. 한국어 번역, 독립 역번역, 전문가 조정
4. 목표 사용자 인지 인터뷰
5. 사전 등록된 표본·분석 계획
6. 요인구조, 내적 일관성, 재검사 신뢰도, 측정오차 분석
7. 연령·성별·언어 집단의 문항 편향과 측정 불변성 검토
8. 외부 심리측정 전문가의 결과 카피 검토

표본 수는 임의의 고정 숫자로 선언하지 않고 요인모형, 집단 비교 수, 기대 효과와 탈락률에 따라 통계 자문으로 산정한다. 검증 중에는 내부 또는 제한 베타 상태만 허용한다.

### 10.3 사용자 흐름

```text
목적·비진단 안내
  → 10문항씩 6단계
    → 누락 검토
      → RIASEC 채점
        → 6영역 지도 + 상위 3영역
          → 흥미 기반 탐색 질문
            → 방법·한계·출처
```

- 예상 소요시간과 진행률을 시작 전에 제공한다.
- 문항에는 `좋아함/싫어함`을 묻는 것이며 능숙함을 묻는 것이 아니라고 설명한다.
- 중간 저장은 브라우저 세션에만 두고 원응답을 서버로 보내지 않는다.
- 직업 탐색 연결은 O*NET 직업 데이터의 지역·시점 한계를 표시한다.
- 한국 노동시장 직업 추천으로 직접 변환하지 않는다. 국내 직업 데이터 연결은 별도 검증 작업이다.

### 10.4 결과 구성

- 상위 3개 흥미 영역과 여섯 영역 전체 프로필
- 조합이 드러내는 선호 활동과 업무 환경
- 인접·대조 영역의 긴장과 조건
- 스스로 확인할 경험 질문
- 탐색할 직업 활동 예시
- 검사 버전, 언어, 검증 상태, 출처, 한계

## 11. 홈·UI·UX 설계

### 11.1 정보구조

현재 만다라 노드와 기능 카드의 중복을 줄이고 네 가지 사용자 목적을 중심으로 탐색한다.

- 전통·상징: 사주, 점성술, 타로, 수비학, 운세
- 성향·관계: Big Five, 융 유형, 애착, 다크 트라이어드, 궁합
- 커리어·동기: RIASEC, 향후 자기효능감·기본욕구
- 오늘: 오늘의 운세, 최근 결과, 이어하기

첫 화면에는 추천 또는 최근 사용 기능 세 개와 목적군을 보여 준다. 전체 분석은 명시적 `전체 분석 보기`에서 펼친다. 데스크톱 만다라는 선택형 탐색 레이어로 남기고, 모바일은 압축 목록을 기본으로 한다.

기능 카드에는 다음을 일관되게 표시한다.

- 소요시간과 문항 수
- 분석 종류와 검증 상태
- 결과 형태
- 로컬 처리 여부
- 추천 목적

### 11.2 가독성과 접근성

- 긴 본문 기본 글자 크기는 16px 이상, 보조 정보는 12px 미만으로 내리지 않는다.
- 주요 터치 대상은 최소 44×44px를 유지한다.
- 키보드 포커스는 모든 hover 정보와 동일한 정보를 제공한다.
- 장식 배경 위에 긴 본문을 직접 놓지 않는다.
- 색상만으로 근거 상태나 점수를 구분하지 않는다.
- 390px, 768px, 1440px 기준 화면을 검증한다.

### 11.3 모션

모션을 세 종류로 제한한다.

- 기능 모션: 진행, 선택, 점수 공개, 오류 복구
- 구조 모션: 섹션 전환과 점진적 공개
- 분위기 모션: 배경 입자, 광원, 3D 만다라

기능 모션은 유지하되 분위기 모션은 저사양·모바일·reduced-motion에서 끈다. 필수 콘텐츠를 초기 opacity 0 상태에 의존시키지 않는다. 3D는 동적 로드되는 선택 기능이며 DOM/SVG 대체 탐색을 항상 제공한다.

### 11.4 이미지

- 원본 PNG는 배포 자산과 분리한다.
- 실제 이동·삭제 전에 파일 목록, 해시, 복구 위치를 제시하고 승인을 받는다.
- 프로덕션에는 반응형 AVIF/WebP와 필요한 fallback만 둔다.
- 이미지 매니페스트에 경로, 크기, 비율, 대체 텍스트, 출처, 팔레트를 기록한다.
- LCP 이미지는 지연 로드하지 않고 정확한 `sizes`와 우선순위를 준다.
- 아래 영역 이미지는 지연 로드하고 blur placeholder를 사용한다.
- 첫 모바일 뷰 이미지 200KB 이하, 일반 라우트 초기 이미지 1.2MB 이하를 목표로 한다.

## 12. 선택형 Supabase 설계

Phase 0~4는 Supabase 없이 동작한다. 기기 간 기록 동기화 수요가 검증되면 다음 최소 구조만 도입한다.

```text
profiles
  id = auth.uid()

assessment_runs
  id
  user_id
  method_key
  instrument_version
  schema_version
  score_summary
  created_at
```

- 원응답 컬럼은 기본 스키마에 넣지 않는다.
- 모든 SELECT/INSERT/UPDATE/DELETE 정책은 `auth.uid() = user_id`를 전제로 한다.
- anon 클라이언트는 RLS를 우회하지 못한다.
- `service_role`은 서버 전용 관리·마이그레이션 작업에서만 사용한다.
- 보존기간, 사용자 내보내기, 개별·전체 삭제 기능을 함께 제공한다.
- 마이그레이션 실행은 SQL 검토 후 별도 승인을 받는다.

Vercel에서는 기본 Node.js Fluid Compute를 사용하며 이 기능을 위해 Edge 런타임을 도입하지 않는다. 배포 검증 전에 Vercel CLI를 설치해 `vercel env pull`, Preview 배포, 로그 확인 절차를 마련한다.

## 14. 출시 전략

- Phase 0은 기능 플래그 없이 전 사용자에게 적용할 수 있는 정합성·개인정보 수정으로 구성한다.
- 척도 변경은 기존 버전과 새 버전을 혼합하지 않고 `instrumentVersion`으로 분리한다.
- RIASEC는 내부 검토 → 제한 베타 → 검증 상태 공개 베타 → 프로덕션 순으로 승격한다.
- 검증 전 RIASEC는 홈의 정식 분석 수에 포함하지 않는다.
- 이미지 정리는 새 파생 자산이 동일 경로에서 검증된 후 별도 승인으로 원본을 이동한다.
- Supabase는 로컬 전용 경로가 완전히 유지되는 상태에서 선택 기능으로 출시한다.

## 17. 승인된 결정 요약

1. 제품 중심 가치는 `신뢰도 + 자기이해`다.

7. 홈은 첫 기능 선택을 유지하되 목적군과 점진적 공개로 압축한다.

# LUMINA 애착 결과 세션 실행 경계 계획

## 목표

Phase 0A 다음의 첫 개인정보 경계 수직 단위로 애착 검사 제출 흐름을 세션 기반 opaque `run` URL로 전환한다. 브라우저 세션에 원응답을 저장하지 않고, 엔진이 계산한 `AttachmentView` 파생 결과만 저장한다.

## 범위

- `AssessmentRunV1` 공통 계약과 `sessionStorage` 저장·검증·삭제 함수
- 애착 제출 시 `?run=<opaque-id>`로 이동
- 애착 결과에서 클라이언트가 세션의 파생 결과를 읽어 렌더링
- 잘못된 실행·저장 공간 오류·저동작 환경의 복구 경로
- 기존 `?r=` 링크는 즉시 폐기하지 않고 호환용 읽기 경로로 유지

## 경계

- 서버·Supabase·외부 API로 원응답을 보내지 않는다.
- `AssessmentRunV1.scoreSummary`에는 원응답·출생정보·식별정보를 넣지 않는다.
- 클라이언트 컴포넌트는 세션 실행 로딩과 결과 상호작용만 담당하고, 계산은 순수 엔진/뷰 모델을 사용한다.
- `service_role` 또는 비밀키를 사용하지 않는다.

## 완료 조건

1. 애착 신규 제출 URL은 `run`만 포함하고 원응답 문자열을 포함하지 않는다.
2. 세션이 없거나 요약 구조가 손상되면 다시 검사 안내를 보여 준다.
3. 한국어·영어 메시지 키가 일치한다.
4. 저장 계약 단위 테스트와 36문항 제출 E2E가 통과한다.
5. 기존 전체 테스트·타입체크·린트·빌드가 회귀 없이 통과한다.

## 다음 단위

동일 계약을 Big Five·다크 트라이어드에 확장한 뒤, URL의 `r` 호환 경로 제거 여부를 개인정보 영향평가와 공유 UX 검토 후 결정한다.
